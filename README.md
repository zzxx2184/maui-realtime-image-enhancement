# .NET MAUI 기반 실시간 명암 보정 및 안티-글레어 렌더링

모바일 카메라 영상과 갤러리 이미지의 밝기·대비를 조절하여 저조도 및 강한 조명 환경에서 가시성을 높이는 애플리케이션입니다.

카메라 프레임 처리, 밝기 분석, 색상 행렬 기반 보정을 구현하고 Android 실기기에서 동작과 자원 사용량을 확인했습니다.

## 프로젝트 정보

- 개발자: 이성무
- 진행 기간: 2026.06 ~ 2026.09
- 사용 기술: C#, .NET 9, .NET MAUI, Android CameraX, SkiaSharp
- 분석 도구: Python, OpenCV, ADB
- 테스트 기기: Samsung Galaxy SM-A366N

## 담당 역할

- 카메라 프레임 수집 및 데이터 변환 구현
- 카메라 처리와 렌더링 계층 분리
- 평균 밝기 분석 및 보정 강도 제어
- 색상 행렬 기반 밝기·대비 보정 구현
- 알고리즘별 보정 결과 및 Sobel 윤곽선 비교
- Android 실기기 동작 및 자원 사용량 확인

## 주요 기능

### 실시간 카메라 및 갤러리 이미지 보정

카메라 프리뷰와 갤러리 이미지에 명암 보정을 적용합니다. 슬라이더로 보정 강도를 조절하며 결과를 확인할 수 있습니다.

### 10×10 그리드 기반 밝기 분석

전체 픽셀을 순회하는 대신 10×10 그리드에서 샘플 픽셀을 추출합니다. RGB 값으로 휘도를 계산하고 평균 밝기를 보정 강도 결정에 활용합니다.

### EMA 기반 보정 강도 평활화

조명 변화에 따라 보정값이 급격하게 바뀌는 현상을 완화하기 위해 지수 이동 평균을 적용했습니다.

이전 보정값에 0.9, 새로운 목표값에 0.1의 가중치를 부여하여 보정 강도를 점진적으로 변경합니다.

### White Pivot 색상 행렬 기반 대비 보정

흰색 기준값을 유지하면서 그보다 어두운 영역과의 명암 차이를 강조합니다. 입력 영상에 남아 있는 명암 정보를 활용하며, 완전히 포화되어 소실된 정보를 복원하는 기능은 아닙니다.

## 카메라 처리 구조

1. Android CameraX로 카메라 프레임 수집
2. YUV 데이터를 NV21 형식으로 변환
3. 메모리 내 JPEG 변환 및 비트맵 디코딩
4. 샘플 픽셀을 활용한 평균 밝기 분석
5. 보정 강도 계산 및 EMA 적용
6. 색상 행렬 적용 및 SkiaSharp 렌더링

프레임 데이터는 백그라운드에서 처리하고, 중간 프레임을 디스크에 저장하지 않도록 구성했습니다.

## 문제 해결 과정

| 확인한 문제 | 적용한 방법 |
|---|---|
| 외부 비전 라이브러리의 호환성 문제 | 필요한 보정 연산을 C#과 SkiaSharp 중심으로 구현 |
| 전체 픽셀 분석의 처리 부담 | 10×10 그리드 샘플링으로 평균 밝기 추정 |
| 카메라 처리와 화면 출력 작업의 부하 | 백그라운드 처리와 렌더링 계층 분리 |
| 조명 변화에 따른 급격한 보정값 변화 | EMA를 활용한 보정 강도 평활화 |
| 강한 빛과 낮은 대비로 잘 보이지 않는 영역 | White Pivot 색상 행렬 기반 대비 조정 |

## 보정 결과 비교

저조도 인물 및 야간 주차장 이미지에 원본, K-Means 클러스터링, 퍼지 스트레칭, 본 프로젝트의 보정 기법을 적용하여 비교했습니다.

- 얼굴·의상 및 바닥 구획선의 가시성 확인
- 보정 방식에 따른 색상 변화와 배경 노이즈 비교
- Sobel 윤곽선 추출을 통한 주요 경계와 노이즈 윤곽선 비교

|---|---|

| 물리 메모리 사용량 | 약 338 MB |

위 수치는 해당 테스트 환경에서 기록한 값입니다. 최적화 전후의 개선율을 의미하지 않으며, FPS는 별도 측정값을 제시하지 않았습니다.

## 실행 방법

1. .NET 9 및 .NET MAUI Android 개발 환경을 준비합니다.
2. 저장소를 다운로드하거나 복제합니다.
3. Visual Studio에서 `lasthomework.csproj`를 엽니다.
4. 필요한 NuGet 패키지를 복원합니다.
5. Android 실행 대상을 선택하여 빌드하고 실행합니다.
6. 카메라 권한을 허용한 뒤 실시간 보정 기능을 확인합니다.

실기기에서 실행하려면 USB 디버깅을 활성화하고 PC에 연결해야 합니다.

## 한계 및 개선 방향

- 화면 평균 밝기를 기준으로 제어하여 밝고 어두운 영역이 공존하는 장면의 영역별 보정에 한계가 있습니다.
- 대비를 강하게 적용하면 일부 영역에서 클리핑이 발생할 수 있습니다.
- 영역별 밝기 분석과 보정 강도 제한을 개선 방향으로 검토하고 있습니다.
- 메모리 내 JPEG 변환과 비트맵 디코딩 비용을 별도로 측정할 계획입니다.
- Android CameraX 기반 카메라 제어 계층을 iOS의 AVFoundation으로 확장할 계획입니다.

## 배운 점

모바일 영상처리에서는 보정 결과의 품질과 함께 프레임 처리 시간, 메모리 사용량, 라이브러리 호환성을 고려해야 한다는 점을 배웠습니다.

영상 보정 알고리즘을 실제 카메라 처리 과정에 연결하고 실기기에서 동작을 확인하며, 알고리즘과 애플리케이션 구조를 함께 설계하는 경험을 쌓았습니다.
