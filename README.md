# .NET MAUI 기반 실시간 명암 보정 앱

Android 카메라 영상과 갤러리 이미지의 밝기·대비를 조절하는 애플리케이션입니다.

실시간 카메라에서는 퍼지 제어와 EMA를 이용해 보정 배율을 자동으로 계산합니다. 수동 카메라 모드와 갤러리에서는 슬라이더로 밝기·대비를 조절하고, 결과 이미지를 JPEG로 생성하여 공유할 수 있습니다.

## 프로젝트 정보

- 개발자: 이성무
- 진행 기간: 2026.06 ~ 2026.10
- 구분: 팀 프로젝트
- 사용 기술: C#, .NET 9, .NET MAUI, Android CameraX, SkiaSharp
- 이미지 분석 및 비교: Python, OpenCV
- 동작 확인 기기: Samsung Galaxy SM-A366N

## 담당 역할

- 본인: 앱 설계, 전체 기능 구현, 실험 및 분석
- 팀원: 실험용 이미지 수집

직접 구현한 주요 내용은 다음과 같습니다.

- 카메라 프레임 수집과 이미지 형식 변환
- 카메라 프레임 변환 계층과 화면 렌더링 계층 분리
- 밝기 샘플링과 퍼지 기반 자동 보정
- EMA를 이용한 보정값 평활화
- 색상 행렬 기반 밝기·대비 조절
- 프레임 캡처, 갤러리 이미지 불러오기, 결과 저장·공유

## 주요 기능

### 1. 실시간 자동 보정

자동 모드는 실시간 카메라에만 적용되며, 앱의 초기 상태는 자동 ON입니다.

영상 너비·높이의 약 1/10 간격으로 픽셀을 샘플링하고 다음 값을 계산합니다.

- 평균 휘도
- 암부 샘플 비율: 휘도 90 이하
- 하이라이트 샘플 비율: 휘도 225 이상

픽셀의 휘도는 다음 식으로 계산합니다.

Y = 0.299R + 0.587G + 0.114B

평균 휘도로 어두움·보통·밝음의 소속도를 계산하고, 암부와 하이라이트 비율을 보조 입력으로 반영합니다.

| 밝기 상태 | 기본 소속도 함수 | 규칙 출력 배율 |
| --- | --- | --- |
| 어두움 | LeftShoulder(L, 80, 120) | 2.15 |
| 보통 | Trapezoid(L, 90, 125, 175, 195) | 1.00 |
| 밝음 | RightShoulder(L, 175, 215) | 0.50 |

보완된 소속도를 가중치로 사용하여 세 규칙의 출력 배율을 가중평균합니다.

자동 목표 배율은 코드에서 0.5~2.2로 제한합니다. 현재 규칙의 가중평균으로 계산되는 목표 배율은 0.5~2.15 범위입니다.

프레임 전체에 하나의 배율을 적용하는 전역 보정 방식이며, 영역마다 서로 다른 배율을 적용하지는 않습니다.

### 2. EMA 기반 보정값 평활화

퍼지 제어로 계산한 목표 배율이 화면에 급격하게 반영되지 않도록 EMA를 적용합니다.

새 보정값 = 이전 보정값 × 0.8 + 목표 보정값 × 0.2

자동 모드에서는 계산된 보정값을 RGB 채널에 곱합니다. 슬라이더는 사용자 입력을 비활성화하고 현재 보정값을 참고용으로 표시합니다.

### 3. 수동 밝기·대비 조절

카메라 자동 모드를 끄거나 갤러리 이미지를 선택하면 슬라이더로 보정 강도를 조절할 수 있습니다.

수동 슬라이더 범위는 0.1~8.0입니다.

- 강도 1 이상: RGB 채널에 해당 강도를 곱합니다.
- 강도 1 미만: 아래 계수와 오프셋으로 대비를 조절합니다.

S = 1 + (1 − I) × 3
O = 1 − S

계산한 값을 SkiaSharp 색상 행렬에 전달합니다. 알파 채널은 유지합니다.

자동 모드의 RGB 배율 보정과 수동 모드의 대비 보정은 서로 다른 계산 경로를 사용합니다.

### 4. 동적 렌더링 스케일 조절

자동 모드에서는 렌더링 콜백에서 계산한 처리시간과 호출 빈도를 참고하여 대상 비트맵의 가로·세로 배율을 0.5 또는 1.0으로 조절합니다.

가로·세로를 각각 0.5배로 축소하면 대상 비트맵의 픽셀 수는 약 1/4이 됩니다. 이는 전체 처리시간이나 메모리 사용량이 1/4로 감소한다는 의미는 아닙니다.

최적화 전후의 성능 개선율은 별도로 측정하지 않았습니다.

### 5. 캡처 및 결과 공유

- 현재 카메라 프레임을 캡처하여 갤러리 화면으로 전달
- 기기에 저장된 이미지 불러오기
- 갤러리 이미지의 수동 보정
- 보정 결과를 앱 캐시에 JPEG로 생성
- Android 공유 화면을 통한 파일 공유

## 카메라 처리 구조

1. CameraX ImageAnalysis로 프레임을 수신합니다.
2. 백그라운드 실행기에서 YUV 데이터를 변환하고 메모리 내 JPEG를 생성합니다.
3. JPEG를 SKBitmap으로 디코딩하여 FrameReady 이벤트로 전달합니다.
4. MainPage에서 lock으로 보호하며 프레임 비트맵을 교체합니다.
5. 화면 그리기 콜백에서 필요에 따라 비트맵을 축소하고 밝기를 분석합니다.
6. 자동 모드에서는 퍼지 제어와 EMA로 보정 배율을 계산합니다.
7. 색상 행렬을 적용하여 SkiaSharp으로 화면에 출력합니다.

CameraX에는 최신 프레임을 우선 처리하는 KEEP_ONLY_LATEST 전략을 적용했습니다. 사용이 끝난 카메라 프레임은 finally에서 닫습니다.

카메라 프레임 변환은 백그라운드에서 수행하며, 밝기 분석과 보정·출력은 화면 그리기 콜백에서 수행합니다. 실시간 프리뷰의 중간 프레임은 디스크에 저장하지 않습니다.

## 보정 결과 비교

저조도 인물 및 야간 주차장 이미지에 K-Means, 퍼지 스트레칭과 본 프로젝트의 보정을 적용하여 원본과 비교했습니다.

본 프로젝트의 비교 이미지는 갤러리 수동 보정으로 생성했습니다. 실시간 자동 보정의 성능 평가와는 구분됩니다.

- 얼굴·의상 및 바닥 구획선의 가시성 비교
- 보정 방식에 따른 색상 변화와 배경 노이즈 관찰
- Sobel 윤곽선 결과를 통한 주요 경계와 배경 윤곽선 비교

시각적 관찰을 중심으로 한 정성 비교이며, OCR 인식률이나 객체 탐지 정확도의 향상을 입증한 결과는 아닙니다.

## 실행 방법

1. .NET 9 SDK와 .NET MAUI Android 개발 환경을 준비합니다.
2. 저장소를 다운로드하거나 복제합니다.
3. Visual Studio에서 lasthomework.csproj를 엽니다.
4. NuGet 패키지를 복원합니다.
5. Android 실행 대상을 선택하여 빌드하고 실행합니다.
6. 앱의 카메라 권한을 허용합니다.

실기기로 실행하려면 개발자 옵션에서 USB 디버깅을 활성화하고 PC에 연결합니다.

빌드에는 소스 파일 외에도 프로젝트에서 참조하는 Platforms, Resources 등의 파일이 필요합니다.

## 사용 방법

1. 앱을 실행하면 실시간 카메라 화면이 표시됩니다.
2. 자동 ON에서는 주변 밝기에 따라 보정 배율을 계산합니다.
3. 자동 OFF에서는 슬라이더로 보정 강도를 직접 조절합니다.
4. 캡처 버튼을 누르거나 갤러리에서 이미지를 불러옵니다.
5. 갤러리 화면에서 보정 강도를 조절합니다.
6. 저장 버튼을 누르면 보정된 JPEG를 생성하고 공유 화면을 엽니다.

## 한계 및 개선 방향

- 프레임 전체에 하나의 보정 배율을 적용하므로 밝고 어두운 영역을 각각 보정하는 데에는 한계가 있습니다.
- 강한 보정은 클리핑을 유발할 수 있으며, 이미 소실된 영상 정보는 복원하지 못합니다.
- 다양한 Android 기기에서 영상 변환과 화면 회전의 호환성을 확인할 필요가 있습니다.
- 반복되는 수동 보정 행렬 계산을 공통 함수로 분리할 계획입니다.
- JPEG 변환·비트맵 디코딩 비용과 프레임 처리시간을 별도로 측정할 계획입니다.
- 보정 전후의 OCR 인식률과 객체 탐지 정확도를 비교할 계획입니다.

## 배운 점

카메라 프레임 수집부터 보정·화면 출력·저장까지 연결하며, 프레임 동기화와 비트맵 자원 관리를 경험했습니다.

또한 퍼지 제어와 EMA를 결합해 자동 보정값을 계산하고, 자동 모드와 수동 모드의 처리 방식을 구분하여 구현했습니다.
